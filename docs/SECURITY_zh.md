# 安全说明：私钥、结果文件与发布前检查

本文件面向用户、文档维护者和后续 GUI / Release agent。核心原则：**私钥就是资产控制权**。

## 1. 用户必须知道的事

- 地址可以公开，私钥不能公开。
- 任何拿到私钥的人，都可以转走该地址里的 TRX、USDT-TRC20 和其他 TRC20 资产。
- 本项目默认隐藏私钥，默认输出文件不包含私钥。
- 高风险参数 `--show-private-key` 会把私钥打印到终端。
- 高风险参数 `--allow-plaintext-private-key-output` 会允许私钥写入明文输出文件。
- 不要把私钥发送到 Telegram、微信、GitHub、网盘、邮箱、截图同步相册或不可信网站。

## 2. 推荐保存方式

低风险使用：

1. 先只保存地址和命中规则。
2. 如果必须保存私钥，在可信、离线或最小联网环境中操作。
3. 使用加密介质或加密文件保存。
4. 不把结果文件提交到 Git，不把结果文件上传到云端同步目录。
5. 高价值地址先做小额转账测试。

## 3. 不推荐行为

- 在共享电脑、网吧、远程协助会话中生成私钥。
- 开着屏幕共享、录屏、自动终端日志时显示私钥。
- 把明文私钥粘贴到在线工具中验证。
- 使用真实私钥做 README、官网、截图或测试素材。
- 把真实命中结果 CSV 发给他人“帮忙看看”。

## 4. 文档 / 官网截图规范

允许：

- 使用 `Txxxxxxxxxxxxxxxxxxxxxxxxxxxxx8888` 这类地址占位。
- 使用 `Private key hidden by default` 这类安全提示截图。
- 使用明确标注 `FAKE / PLACEHOLDER / DO NOT USE` 的短占位文本。

禁止：

- 真实私钥。
- 真实结果 CSV。
- bot token、API key、`.env` 内容。
- 看起来像真实 64 位十六进制私钥的示例字符串。
- 未脱敏的终端历史、用户名、路径中包含敏感信息的截图。

## 5. Release 前安全检查

发布文档、官网或安装包前至少检查：

```bash
git diff --check
```

并人工搜索以下敏感信息类型：

- `PRIVATE_KEY`
- `BOT_TOKEN`
- `API_KEY`
- `.env`
- `--show-private-key`
- `--allow-plaintext-private-key-output`

注意：搜索到高风险参数不一定是问题；文档中可以出现它们，但必须明确标注风险，不能作为默认推荐路径。

## 6. 产品文案边界

不要这样说：

- “保证安全”。
- “保证多久命中”。
- “GPU 一定百万级速度”。
- “普通用户已可一键安装”（在 installer 发布前）。

可以这样说：

- “本地生成，默认隐藏私钥”。
- “预计时间是概率估算，不是保证”。
- “当前为开发者 CLI alpha；GUI / installer 在路线图中”。
- “实际速度取决于硬件、驱动、OpenCL、batch size 和版本”。
