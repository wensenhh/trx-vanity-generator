## 1. 项目简介

TRX Vanity Generator 是一个**本地离线**的 TRON（TRX）靓号地址生成器。它在你自己的电脑上通过 CPU 或 GPU 加速，不断生成 TRON 地址，直到找到符合你指定规则的地址。

**核心特性：**

- **完全离线**：私钥不会上传到任何服务器
- **CPU / GPU 双模式**：支持 OpenCL GPU 加速
- **多种匹配规则**：后缀、前缀、包含、连号、顺子
- **私钥安全**：默认隐藏，支持加密导出
- **跨平台**：Windows、macOS、Linux

**当前版本定位：**

- CLI（命令行）：可用，适合开发者和技术用户
- GUI（图形界面）：FLTK 桌面应用已可用，需自行编译
- 安装包：macOS DMG、Windows ZIP 可通过源码构建生成

## 2. 安全须知

### ⚠️ 核心原则：私钥就是资产控制权

谁拿到私钥，谁就能控制对应地址里的 **TRX、USDT-TRC20 和所有 TRC20 资产**。

### 默认安全行为

| 场景 | 行为 |
|------|------|
| 终端输出 | 默认隐藏私钥 |
| `-o/--output` 结果文件 | 默认不包含私钥 |
| 加密导出 | AES-256-GCM 加密，密码不写入文件 |
| 明文私钥文件导出 | **已禁用** |

### 高风险操作

```bash
# ⚠️ 高风险：把私钥打印到终端
--show-private-key

# ⚠️ 中风险：密码可能进入 shell history
--export-password <密码>

# ✅ 推荐：从环境变量读取密码
--export-password-env <变量名>
```

### 绝对禁止

- ❌ 把私钥发到 Telegram、微信、GitHub
- ❌ 把私钥保存到网盘、邮箱、截图同步相册
- ❌ 在共享电脑、网吧、远程协助中生成私钥
- ❌ 开着屏幕共享或录屏时显示私钥
- ❌ 把真实结果 CSV 发给他人"帮忙看看"

### 推荐保存流程

1. 先只保存地址和命中规则
2. 如需保存私钥，在**可信、离线**环境中操作
3. 使用 `--encrypted-output` 加密保存
4. 高价值地址先做**小额转账测试**

## 3. 功能概览

### 支持的靓号规则

| 规则类型 | 说明 | 示例 |
|----------|------|------|
| `suffix` | 后缀匹配 | `8888` → `T...8888` |
| `prefix` | 前缀匹配（T 之后） | `ABC` → `TABC...` |
| `contains` | 包含某段字符 | `520` → `T...520...` |
| `consecutive` | 连续重复字符 | `8 7` → `T...8888888` |
| `sequential` | 顺子数字 | `1 7` → `T...1234567` |

### 生成方式

- **CPU 模式**：适合所有设备，无需额外驱动
- **GPU 模式**：需要 OpenCL 支持，速度更快

### 输出方式

- **终端显示**：默认只显示地址
- **文件保存**：`-o results.csv`，默认不含私钥
- **加密导出**：`--encrypted-output`，AES-256-GCM 加密

## 4. 安装与构建

### Windows

#### 前提条件

1. **Visual Studio 2022 Community**（勾选 `Desktop development with C++`）
2. **CMake**（或使用 VS 自带）
3. **vcpkg** + OpenSSL

#### 安装依赖

```powershell
# 安装 vcpkg
git clone https://github.com/microsoft/vcpkg C:\vcpkg
C:\vcpkg\bootstrap-vcpkg.bat
C:\vcpkg\vcpkg install openssl:x64-windows
```

#### 编译

```powershell
cd C:\path\to\trx_addr
cmake -S . -B build -A x64 -DBUILD_TESTS=ON `
  -DCMAKE_TOOLCHAIN_FILE=C:\vcpkg\scripts\buildsystems\vcpkg.cmake

cmake --build build --config Release --parallel

# 运行测试
ctest --test-dir build -C Release --output-on-failure
```

#### 运行

```powershell
# Smoke test（验证安装）
.\build\Release\trx_vanity.exe prefix T --max-attempts 64 -t 1

# 简单规则
.\build\Release\trx_vanity.exe consecutive 8 7 -t 8 -v

# GPU 模式
.\build\Release\trx_vanity.exe consecutive 8 7 --gpu --batch-size 65536 -v
```

#### 可选：构建 GUI

```powershell
cmake -S . -B build -A x64 -DBUILD_GUI=ON -DBUILD_TESTS=ON `
  -DCMAKE_TOOLCHAIN_FILE=C:\vcpkg\scripts\buildsystems\vcpkg.cmake

cmake --build build --config Release --parallel
# 运行 GUI
.\build\Release\trx_vanity_gui.exe
```

## 6. 规则详解

### suffix — 后缀匹配

找地址末尾为指定字符串的地址。

```bash
# 尾号 8888
./trx_vanity suffix 8888

# 尾号 5201314
./trx_vanity suffix 5201314
```

### prefix — 前缀匹配

TRON 地址固定以 `T` 开头，`prefix` 匹配 `T` 之后的内容。

```bash
# 地址以 TABC 开头
./trx_vanity prefix ABC
```

### contains — 包含匹配

地址任意位置包含指定字符串（包括固定的 `T`）。

```bash
# 地址中包含 520
./trx_vanity contains 520
```

### consecutive — 连续重复

地址末尾有指定数量的连续重复字符。

```bash
# 7 个连续的 8
./trx_vanity consecutive 8 7

# 8 个连续的 8（更难）
./trx_vanity consecutive 8 8
```

### sequential — 顺子

地址末尾为递增数字序列。

```bash
# 末尾是 1234567
./trx_vanity sequential 1 7

# 末尾是 2345678
./trx_vanity sequential 2 7
```

## 7. 命令行参数

### 基本参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `-t, --threads <n>` | CPU 线程数 | `-t 8` |
| `--max-attempts <n>` | 最大尝试次数后停止 | `--max-attempts 1000000` |
| `-v, --verbose` | 显示进度 | `-v` |
| `-o, --output <file>` | 保存结果文件 | `-o results.csv` |
| `-h, --help` | 显示帮助 | `-h` |

### GPU 参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `--gpu` | 启用 GPU 加速 | `--gpu` |
| `--batch-size <n>` | GPU 每批处理数量 | `--batch-size 65536` |
| `--batches <n>` | 跑固定批数后停止 | `--batches 10` |
| `--device <p:d>` | 指定 GPU 设备 | `--device 1:1` |
| `--auto-tune` | 自动测试最优 batch size | `--auto-tune` |
| `--auto-tune-sizes` | 候选 batch sizes | `--auto-tune-sizes 32768,65536,131072` |
| `--profile` | 打印每批耗时 | `--profile` |
| `--benchmark-json` | 输出 JSON 格式基准 | `--benchmark-json` |
| `--gpu-verify` | CPU 复核 GPU 结果 | `--gpu-verify` |

### 安全参数

| 参数 | 说明 | 风险等级 |
|------|------|----------|
| `--show-private-key` | 终端显示私钥 | ⚠️ 高 |
| `--encrypted-output <file>` | 加密导出结果 | ✅ 低 |
| `--export-password <pw>` | 直接提供密码 | ⚠️ 中 |
| `--export-password-env <name>` | 从环境变量读密码 | ✅ 低 |
| `--allow-plaintext-private-key-output` | 明文导出（已禁用） | ❌ 禁用 |

### 完整示例

```bash
# CPU 模式，8 线程，verbose，保存结果
./trx_vanity suffix 8888 -t 8 -v -o results.csv

# GPU 模式，自动调优，verbose
./trx_vanity consecutive 8 7 --gpu --auto-tune -v

# GPU 模式，指定设备，小批量测试
./trx_vanity prefix T --gpu --batch-size 64 --batches 1 --device 1:1

# 加密导出含私钥结果
export TRX_EXPORT_PASSWORD="strong-unique-password-123"
./trx_vanity suffix 8888 --encrypted-output vault.trxenc --export-password-env TRX_EXPORT_PASSWORD

# 高风险：显示私钥（确认环境安全后再用）
./trx_vanity suffix 8888 --show-private-key
```

## 8. GPU 加速

### 检查 GPU 支持

```bash
# 查看可用的 OpenCL 设备
./trx_vanity prefix T --gpu --batch-size 64 --batches 1
```

如果报错，检查：

1. 显卡驱动是否最新
2. `TRX_KERNEL_DIR` 是否设置正确
3. `--batch-size` 是否过大

### 设置 Kernel 目录

如果程序找不到 `vanity.cl`：

```bash
# macOS / Linux
TRX_KERNEL_DIR=/path/to/trx_addr/kernel ./trx_vanity suffix 8888 --gpu

# Windows PowerShell
$env:TRX_KERNEL_DIR="C:\path\to\trx_addr\kernel"
.\trx_vanity.exe suffix 8888 --gpu
```

### 安装后使用

```bash
# 先安装到固定目录
cmake --install build --prefix /opt/trx_vanity

# 然后运行
TRX_KERNEL_DIR=/opt/trx_vanity/share/trx_vanity/kernel \
  /opt/trx_vanity/bin/trx_vanity suffix 8888 --gpu --batch-size 65536
```

### Auto-Tune 自动调优

让程序自动测试多个 batch size，选择最快的：

```bash
./trx_vanity consecutive 8 7 --gpu --auto-tune -v
```

### GPU 验证模式

对 GPU 命中的地址用 CPU 重新计算验证：

```bash
./trx_vanity consecutive 8 7 --gpu --batch-size 65536 --gpu-verify -v
```

## 9. 结果导出

### 标准输出（默认不含私钥）

```bash
./trx_vanity suffix 8888 -o results.csv
```

文件内容示例：

```csv
address,pattern,attempts,private_key_hidden
Txxxxxxxxxxxxxxxxxxxxxxxxxxxxx8888,suffix 8888,12345678,yes
```

### 加密导出（含私钥）

**推荐方式：**

```bash
# 1. 设置密码环境变量
export TRX_EXPORT_PASSWORD="your-very-strong-password-here"

# 2. 运行并导出
./trx_vanity suffix 8888 --encrypted-output vault.trxenc --export-password-env TRX_EXPORT_PASSWORD
```

**不推荐（密码可能泄露）：**

```bash
./trx_vanity suffix 8888 --encrypted-output vault.trxenc --export-password "password123"
```

### 终端显示私钥（高风险）

```bash
# ⚠️ 确认以下事项后再使用：
# - 电脑可信，无屏幕录制
# - 无终端日志同步
# - 周围无人
./trx_vanity suffix 8888 --show-private-key
```

## 12. 常见问题

### Q1：程序一直跑没有输出，是不是卡住了？

不一定。加 `-v` 看 `Attempts` 是否在增长：

```bash
./trx_vanity suffix 8888888 -v
```

如果 Attempts 持续增长，说明程序正常搜索中。规则越长，命中概率越低，等待时间越长。

### Q2：怎么停止程序？

按 `Ctrl + C`。

### Q3：GPU 报错怎么办？

排查步骤：

1. 先跑 CPU smoke test 确认基础环境正常
2. 检查显卡驱动是否最新
3. 检查 `TRX_KERNEL_DIR` 是否指向正确的 kernel 目录
4. 尝试更小的 `--batch-size`（如 64、1024）
5. 查看具体错误信息，搜索 issue

### Q4：为什么 GPU 没有想象中快？

速度取决于：

- 显卡型号和性能
- 显卡驱动版本
- OpenCL runtime 实现
- batch size 设置
- 系统散热和负载

当前 alpha 版本以**正确性优先**，不承诺极限性能。

### Q5：结果文件能上传给别人看吗？

**不要上传含私钥的文件。**

如果只需要求助技术问题，只提供脱敏日志（删除私钥、地址部分打码）。

### Q6：7 连尾和 8 连尾有什么区别？

Base58 字符集约 58 个字符。每多 1 位，难度约乘以 58：

| 规则 | 相对难度 |
|------|----------|
| 3 位后缀 | 容易 |
| 4 位后缀 | 普通测试 |
| 7 连尾 | 明显困难，需耐心 |
| 8 连尾 | 比 7 连尾难约 58 倍 |

### Q7：预计时间准确吗？

**不准确，只是概率估算。**

程序显示的 ETA 是基于当前速度的粗略估计，不是承诺。实际命中时间可能大幅偏离估计值。

### Q8：可以同时跑多个规则吗？

当前版本一次只能指定一个规则。如需多个规则，可以开多个终端实例（注意资源占用）。

## 13. 故障排查

### 构建失败

| 问题 | 解决 |
|------|------|
| CMake 找不到 OpenSSL | 设置 `-DOPENSSL_ROOT_DIR` |
| Windows 找不到 OpenCL | 安装显卡驱动 |
| macOS 编译错误 | 确认 Xcode Command Line Tools 已安装 |
| Linux 缺少头文件 | 安装 `libssl-dev` `opencl-headers` |

### 运行时错误

| 错误 | 原因 | 解决 |
|------|------|------|
| `CL_INVALID_BUILD_OPTIONS` | OpenCL include 路径含空格 | 已修复，更新到最新版本 |
| `vanity.cl not found` | kernel 文件路径错误 | 设置 `TRX_KERNEL_DIR` |
| `No OpenCL platforms` | 无 OpenCL 支持 | 使用 CPU 模式或安装驱动 |
| `Out of resources` | batch size 过大 | 减小 `--batch-size` |

### 性能问题

| 现象 | 可能原因 | 解决 |
|------|----------|------|
| GPU 速度远低于预期 | batch size 不合适 | 使用 `--auto-tune` |
| CPU 占用 100% | 线程数等于 CPU 核心数 | 正常现象，可限制 `-t` |
| 系统卡顿 | GPU 占用过高 | 减小 batch size 或暂停 |

## 14. 技术规格

### 系统要求

| 平台 | 最低要求 | 推荐配置 |
|------|----------|----------|
| CPU | 任意 x86_64 / ARM64 | 多核处理器 |

### 密码学

- **椭圆曲线**：secp256k1（与 Bitcoin/Ethereum 相同）
- **哈希**：Keccak-256
- **编码**：Base58Check（TRON 地址格式）
- **加密导出**：AES-256-GCM
